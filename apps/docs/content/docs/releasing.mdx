---
title: Releasing
description: How a version of @bloxwap/sfx reaches npm.
---

Releases are published from GitHub Actions on the self-hosted Mac minis.
[npm trusted publishing does not support self-hosted runners](https://docs.npmjs.com/trusted-publishers/),
so the job authenticates with the org-level `NPM_TOKEN` secret (`NODE_AUTH_TOKEN`).
That drops OIDC trusted publishing and automatic provenance.

## Flow

1. Open a PR that bumps `version` in `packages/sfx/package.json` and updates `packages/sfx/CHANGELOG.md`.
2. Merge it after the **Tests**, **Documentation**, and **Security** checks pass.
3. Create a GitHub release tagged `v<version>`, for example `v0.2.0`.
4. The **Publish to npm** workflow checks that the tag matches the package version, verifies `NPM_TOKEN`, runs the full test suite (`prepublishOnly`), and publishes.

Pre-release versions (`0.2.0-beta.1`) publish under the matching dist-tag (`beta`, `alpha`, `rc`) instead of `latest`.

## One-time setup

- Share the bloxwap org `NPM_TOKEN` secret (granular, publish rights for `@bloxwap` packages) with this repository.
- In the repository settings, set GitHub Pages to deploy from **GitHub Actions**.
- Protect `main`, and require the **Tests** check.
- Keep at least one self-hosted Apple Silicon runner online with the labels and tools in [`docs/ci-runners.md`](https://github.com/bloxwap/sfx/blob/main/docs/ci-runners.md). Publish, Pages deploy, and coverage upload all run there.
