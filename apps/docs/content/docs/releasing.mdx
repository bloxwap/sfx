---
title: Releasing
description: How a version of @bloxwap/sfx reaches npm.
---

Releases are built, tested, and packed on self-hosted Apple Silicon Mac minis.
Only the final `publish` job uses GitHub-hosted `ubuntu-24.04`, because
[npm trusted publishing requires GitHub-hosted runners](https://docs.npmjs.com/trusted-publishers/).
That job sets up Node 24 and pinned npm 11.6.1, downloads the prepared tarball by
artifact ID, and publishes it with provenance. It does not check out source,
install project dependencies, or rerun builds and tests.

The `npm-release` environment gates the upload. npm uses OIDC authentication,
with the org-level `NPM_TOKEN` secret as a transitional fallback until the
Trusted Publisher is verified. The separate **Prepare npm release** workflow
remains available for manually publishing signed tarballs with `--provenance-file`.

## Flow

1. Open a PR that bumps `version` in `packages/sfx/package.json` and updates `packages/sfx/CHANGELOG.md`.
2. Merge it after the **Tests**, **Documentation**, and **Security** checks pass.
3. Create a GitHub release tagged `v<version>`, for example `v0.4.0`.
4. The **Publish to npm** workflow runs the security scan, validates the release tag, and skips versions already on npm.
5. On a Mac mini, it installs dependencies, builds and runs the full test suite, and packs the tested build. Packing skips lifecycle scripts to avoid rebuilding.
6. After `npm-release` approval, the hosted job publishes the exact prepared tarball with lifecycle scripts disabled.


Pre-release versions (`0.2.0-beta.1`) publish under the matching dist-tag (`beta`, `alpha`, `rc`) instead of `latest`.

## One-time setup

- Configure the GitHub `npm-release` environment with required reviewers. The YAML environment name alone does not create an approval gate.
- Configure the npm Trusted Publisher for `@bloxwap/sfx`: organization **bloxwap**, repository **sfx**, workflow filename **publish_npm.yml**, environment **npm-release**, allowing direct `npm publish`.
- Keep the org-level `NPM_TOKEN` secret with package write access available as a transitional fallback. After verifying OIDC publishing, remove it and its workflow reference.
- In the repository settings, set GitHub Pages to deploy from **GitHub Actions**.
- Protect `main`, and require the **Tests** check.
- Keep at least one self-hosted Apple Silicon runner online with the labels and tools in [`docs/ci-runners.md`](https://github.com/bloxwap/sfx/blob/main/docs/ci-runners.md). All work except the final npm upload runs there.
